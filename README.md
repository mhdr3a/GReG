      <h2>Entropy-guided Retrieval for Enhanced Multi-hop Open-domain Question Answering</h2>
      <p>We present <b>GReG</b>, a <b>G</b>enerate-<b>Re</b>trieve-<b>G</b>enerate pipeline designed to enhance multi-hop open-domain question answering (ODQA) by leveraging the intrinsic knowledge of large language models (LLMs). Traditional ODQA approaches often rely solely on the internal knowledge of LLMs or augment responses with retrieved passages, but both can struggle with outdated or incomplete information. To address this, our method employs entropy-guided retrieval to adaptively select the most confident long-form answer generated by the LLM, using it as a query for retrieving relevant evidence from external sources. Importantly, GReG requires no additional fine-tuning or architectural modifications, making it well-suited for scenarios where model access is restricted. Our experiments, conducted using the GPT-4o model on four multi-hop QA datasets—MuSiQue, HotpotQA, IIRC, and 2WikiMultihopQA—demonstrate that GReG consistently outperforms simple QA setups and various retrieval-augmented configurations, achieving significant gains in Exact Match (EM) and F1 scores.</p>

1. Replace ```FiD/src/data.py``` with ```GReG/src/data.py```

2. Replace ```FiD/src/evaluation.py``` with ```GReG/src/evaluation.py```


```
<dataset_name> = [MuSiQue, HotpotQA, IIRC, 2WikiMultihopQA]
<model_name> = [gpt-4o]
<retriever_name> = [nq]
<temperature> = [0, 1]
<top_p> = [0.1, 1]
```

Passage retrieval using a pre-trained DPR on NQ:
```
python ../FiD/passage_retrieval.py \
    --model_path ../FiD/pretrained_models/<retriever_name>_retriever \
    --passages ../FiD/open_domain_data/psgs_w100.tsv \
    --data results/<dataset_name>/<model_name>/template_queries_<dataset_name>_<model_name>.jsonl \
    --passages_embeddings ../FiD/wikipedia_embeddings_<retriever_name>_00 \
    --output_path results/<dataset_name>/retrieved_passages_<model_name>_<retriever_name>.json \
    --n-docs 10 \
```

Template query generation:
```
python template_query_generator.py \
    --data data/<dataset_name>/<model_name>/template_queries_<dataset_name>_<model_name>_<temperature>_<top_p>.jsonl \
    --model <model_name> \
    --api_key <your_openai_api_key> \
    --temperature <temperature> \
```

Even if you are generating the factoid answers for the dataset itself, make sure to follow the --data path format to ensure all the parameters are set correctly.
Factoid answer generation using 4 (top_k > 0: with context | top_k = 0: without context) different prompts (metrics are either 0:(EM, ROUGE-F1, Semantic Similarity) or 1:(Sacc, Lacc)):
```
python factoid_answer_generator.py \
      --data results/<dataset_name>/retrieved_passages_<model_name>.json \
      --model <model_name> \
      --top_k <0,1,5,10> \
      --api_key <your_openai_api_key> \
      --metrics <0,1>
```
